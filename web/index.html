이 프로토타입이 하는 일

운영자가 자연어로 지시하면 LLM 이 어떤 API 를 어떤 값으로 부를지 정하고, AI반도체 노드에 추론 서버를 올리고 제어하며, 그 과정을 전부 기록합니다.

요구사항이 인프라가 된다

응용이 gpu x1, 22GiB 이상 이라고만 말하면 어느 CSP 의 어느 인스턴스를 쓸지는 서비스가 정합니다. 코드에 CSP 이름이 없습니다.

쓰기는 기본적으로 막혀 있다

배포·제어·삭제는 등급이 붙어 있고, dry-run 이 켜져 있으면 계획과 검증까지만 하고 멈춥니다. LLM 이 실행 여부를 정하지 않습니다.

만들어진 것과 쓸 수 있는 것은 다르다

노드가 Running 이라고 가속기를 쓸 수 있다는 뜻이 아닙니다. 배포 직후 노드에 직접 물어 카탈로그의 약속과 대조합니다.

왜 그렇게 정했는지가 남는다

최종 결과만이 아니라 지시·고른 도구·인자 전체·게이트가 막았는지까지 한 레코드에 남습니다.

자연어 매칭

  

    "라마 추론서버 올려줘" 가 카탈로그의 어느 항목인가를 정하는 단계입니다.

운영자가 쓰는 말 그대로 넣어 보세요

    

      
      
    

    

    

    

    

  


  

    
읽는 법

    

      구조화된 필드에 걸려야 후보가 됩니다. id·별칭·모델명·런타임·포맷이 그것입니다.
      설명문 단어는 동점을 가르는 데만 쓰이고 혼자서는 후보를 만들지 못합니다.
      흔한 단어 하나로 확신에 찬 오답을 내는 것보다 "없다" 가 낫기 때문입니다.
    

    

      후보가 없으면 빈 목록이 돌아옵니다. 그때 시스템 프롬프트가 모델에게
      "가장 비슷한 것을 배포하지 말고 없다고 답하라" 고 지시합니다.
    

    

      알려진 한계. 점수가 별칭의 길이나 특이도를 반영하지 않아, 별칭이 겹치면 동점이 납니다.
      라마npu 로 검색해 보면 두 응용이 같은 45점으로 나옵니다. 아직 안 고쳤습니다.

무엇이 기록되나

    

      LLM 이 고른 도구와 인자 전체, 도구가 돌려준 응답, 게이트가 막았는지,
      소요 시간까지 한 레코드로 남습니다. 결과만 남기면 왜 그 결정을 했는지가 사라져서,
      2차년도의 "배포 정보 수집 및 추론 재적용" 에 쓸 수 없습니다.
    

  







  
배포와 라이프사이클

  

    여기서 부르는 것은 전부 실제 호출입니다. 이종 클라우드 관리 계층이 붙어 있지 않으면
    실패 응답이 그대로 보입니다. 그것도 동작의 일부라 감추지 않습니다.

가속기 판독 만들어진 것과 쓸 수 있는 것은 다릅니다

    

      
      
    

    

    

    

      노드에서 PCI 버스를 먼저 읽고, 벤더 도구(nvidia-smi·rocm-smi·
      rbln-stat·furiosa-smi·hl-smi·tpu-info)가
      있으면 그 위에 덧칠합니다. 버스는 아무것도 설치돼 있지 않아도 답하므로,
      드라이버가 안 붙은 장치와 아예 없는 장치를 가를 수 있습니다.
    

  


  

    
이 화면에 쓰기 버튼이 없는 이유

    

      실제 생성·제어·삭제 버튼을 의도적으로 넣지 않았습니다. dry-run 이 켜져 있어도 마찬가지입니다.
      되돌릴 수 없고 과금되는 행동을 화면의 버튼 하나에 걸어 두지 않는 것이 이 프로토타입의
      안전장치와 같은 취지입니다. 계획과 검증까지가 여기서 할 수 있는 전부이고,
      실제 생성은 API 를 직접 부르거나 에이전트를 통해서 합니다.
